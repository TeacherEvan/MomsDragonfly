# Environment Setup — Best Practices

> Do NOT commit `.env.local`. It is excluded by `.gitignore` (`.env.local`, `.env*.local`).
> Server secrets go to their deployment environment (Convex via CLI, Vercel via CLI/dashboard), not this repo.

---

## 1. Local Development (`.env.local`)

Copy the template:

```bash
cp .env.local.example .env.local
```

Then edit `.env.local` with your local deployment URLs. Example values from `.env.local.example`:

```env
NEXT_PUBLIC_CONVEX_URL=https://brave-lion-123.convex.cloud
CONVEX_DEPLOYMENT=dev:brave-lion-123
NEXT_PUBLIC_CONVEX_SITE_URL=https://brave-lion-123.convex.site
```

These are safe to keep local — `.env.local` is never committed.

## 2. Vercel Environment Variables

These are the public/project-level variables needed by the deployed Next.js app.

### Variables to set (both `production` and `preview` unless noted):

| Variable | Environment | Notes |
|---|---|---|
| `NEXT_PUBLIC_CONVEX_URL` | production, preview, development | Convex deployment URL |
| `CONVEX_DEPLOYMENT` | production, preview, development | `dev:...` or production deployment name |
| `NEXT_PUBLIC_CONVEX_SITE_URL` | production, preview, development | Convex site URL |

### CLI commands (`vercel env add`):

Run from the project root (requires `vercel login` first):

```bash
# Development
vercel env add NEXT_PUBLIC_CONVEX_URL development
vercel env add CONVEX_DEPLOYMENT development
vercel env add NEXT_PUBLIC_CONVEX_SITE_URL development

# Preview / Production (run each separately; Vercel prompts for value and target environment)
vercel env add NEXT_PUBLIC_CONVEX_URL preview
vercel env add NEXT_PUBLIC_CONVEX_URL production
vercel env add CONVEX_DEPLOYMENT preview
vercel env add CONVEX_DEPLOYMENT production
vercel env add NEXT_PUBLIC_CONVEX_SITE_URL preview
vercel env add NEXT_PUBLIC_CONVEX_SITE_URL production
```

> Alternative: use the Vercel dashboard (Project → Settings → Environment Variables) instead of CLI. Best practice is to set them per-environment (development / preview / production) rather than committing them.

## 3. Convex Server-Side Secrets

These are used by `convex/actions.ts` and related backend functions. Per `GEMINI.md`: **"All Convex secrets via `npx convex env set`, never hardcoded."**

### Variables to set (`dev` and `production`):

| Variable | Required | Source / Note |
|---|---|---|
| `GOOGLE_PLACES_API_KEY` | Yes | Google Places API |
| `BRAVE_SEARCH_API_KEY` | Optional | Brave Search |
| `GEMINI_API_KEY` | Yes | Gemini Vision / actions |
| `GEMINI_MODEL` | Optional | Default: `gemini-1.5-flash` (see `convex/actions.ts`) |
| `VAPID_PUBLIC_KEY` | Yes | Web Push (run `npx web-push generate-vapid-keys`) |
| `VAPID_PRIVATE_KEY` | Yes | Web Push pair |
| `VAPID_SUBJECT` | Yes | `mailto:you@example.com` |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | Browser-safe public key; used by `src/lib/notify.ts` | Set via `vercel env add` or `.env.local` (see `.env.setup.md`) |

### CLI commands (`convex env set`):

```bash
# Dev environment
npx convex env set GOOGLE_PLACES_API_KEY "<your-real-key>" --deployment dev
npx convex env set BRAVE_SEARCH_API_KEY "<your-real-key>" --deployment dev
npx convex env set GEMINI_API_KEY "<your-real-key>" --deployment dev
npx convex env set GEMINI_MODEL "gemini-1.5-flash" --deployment dev
npx convex env set VAPID_PUBLIC_KEY "<your-public-key>" --deployment dev
npx convex env set VAPID_PRIVATE_KEY "<your-private-key>" --deployment dev
npx convex env set VAPID_SUBJECT "mailto:admin@momsdragonfly.app" --deployment dev

# Production environment
npx convex env set GOOGLE_PLACES_API_KEY "<your-real-key>" --deployment production
npx convex env set BRAVE_SEARCH_API_KEY "<your-real-key>" --deployment production
npx convex env set GEMINI_API_KEY "<your-real-key>" --deployment production
npx convex env set GEMINI_MODEL "gemini-1.5-flash" --deployment production
npx convex env set VAPID_PUBLIC_KEY "<your-public-key>" --deployment production
npx convex env set VAPID_PRIVATE_KEY "<your-private-key>" --deployment production
npx convex env set VAPID_SUBJECT "mailto:admin@momsdragonfly.app" --deployment production
```

> Replace `"<your-real-key>"` with actual values. Do NOT paste dummy/placeholder secrets into `dev` or `production`.

### Verify what's set:

```bash
# List dev secrets (names only, values hidden)
npx convex env list --deployment dev

# List production secrets
npx convex env list --deployment production
```

## 4. Best Practice Checklist

- [ ] `.env.local` exists locally and is NOT committed (`.gitignore` covers `.env.local` and `.env*.local`).
- [ ] `.env.local.example` is up to date as the safe template.
- [ ] Convex secrets set via `convex env set`, NOT stored in `.env.local` or source code.
- [ ] Vercel env vars set via `vercel env add` or dashboard, NOT committed in `.vercel/project.json`.
- [ ] `.vercel/project.json` stays in `.gitignore` (already configured).
- [ ] `convex/_generated/` stays in `.gitignore` (already configured).
- [ ] No secrets appear in `convex/actions.ts`, source, or docs.

---

## 5. Quick Reference — What Goes Where

| Variable | Where | Why |
|---|---|---|
| `NEXT_PUBLIC_CONVEX_URL` | `.env.local` (local) + Vercel env (deployed) | Browser-safe; needed by Next.js client |
| `CONVEX_DEPLOYMENT` | `.env.local` (local) + Vercel env (deployed) | Points Convex client to deployment |
| `NEXT_PUBLIC_CONVEX_SITE_URL` | `.env.local` (local) + Vercel env (deployed) | Convex site URL |
| `GOOGLE_PLACES_API_KEY` | `convex env set` (dev + prod) | Server-side Convex action; never exposed to browser |
| `BRAVE_SEARCH_API_KEY` | `convex env set` (dev + prod, optional) | Server-side |
| `GEMINI_API_KEY` | `convex env set` (dev + prod) | Server-side Convex action |
| `GEMINI_MODEL` | `convex env set` (optional) | Server-side |
| `VAPID_*` | `convex env set` (dev + prod) | Server-side push keys |
